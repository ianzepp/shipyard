# Artifact Ladder

Use this ladder to decide what to create next. Do not climb every rung by
default, but do not let the run collapse into one large catch-all file when the
user asked for deep exploration. The next artifact should answer the next real
question, branch point, or validation need.

## 1. Raw Source

Purpose: preserve the user's original thought without laundering it into a
polished interpretation.

Good when:

- the idea is long, messy, or emotionally specific
- later agents will need exact wording
- the user is still discovering the center

## 2. Structured Idea Record

Purpose: turn raw input into a stable object.

Common sections:

- title and slug
- raw sources
- one-line thesis
- operating shape
- audience or first user
- why now
- agent-first read
- assumptions
- open questions

## 3. Index Or Registry

Purpose: compare ideas and track statuses.

Good when:

- more than one idea exists
- statuses matter
- the user wants portfolio-level selection
- an Expansion or Cosmic Background Radiation run needs a corpus map

## 3A. Decision Ledger

Purpose: keep branch points from becoming hidden stopping points.

Common sections:

- decision point
- what is at stake
- provisional choice
- branches explored
- branches parked
- why this choice can be reversed
- evidence that would reverse it

Good when:

- the agent makes a provisional choice instead of asking the user
- several plausible branches remain open
- another model needs to understand why the corpus went deeper in one direction
- the user later wants to audit the path taken

## 4. Pressure-Test Writeback

Purpose: attach reality checks directly to the idea record.

Common sections:

- load-bearing assumptions
- failure modes
- constraint severity
- validation sequence
- promotion triggers
- kill criteria

## 5. Pitch Or Narrative Artifact

Purpose: package the idea for communication after it has been pressure-tested.

Avoid:

- invented traction
- fake TAM
- hiding operational risk
- making an operations-heavy business sound like pure software

## 6. Research Briefs

Purpose: isolate hard unknowns.

Good when:

- a purchase decision depends on current facts
- regulation, market structure, or physical-world constraints matter
- expert review is needed

For deeper Big Bang runs, prefer several focused research briefs over burying
all research inside the root idea record.

## 7. Lifecycle Or Phase Tree

Purpose: convert a concept into a repeatable operating model.

Good when:

- the process has phases
- many artifacts recur by phase
- another agent needs to execute pieces independently
- the branch has been explored far enough to show a possible path to delivery

## 8. Repo-Local Skill

Purpose: capture a repeated process so the next idea can go through it without
re-explaining the method.

Good when:

- the user says "do this same process next time"
- there are stable stages
- the process creates durable artifacts

## 9. Delivery Plan

Purpose: switch from exploration to implementation.

Good when:

- a branch is chosen
- acceptance criteria can be stated
- work can be staged and validated

Use `delivery` for this step when the user wants a real planning artifact rather
than another ideation pass.

## 10. Factory-Ready Phase Set

Purpose: switch from a chosen implementation plan to autonomous multi-phase
execution.

Good when:

- the work is naturally phase-based
- each phase has a checkpoint target
- validation can be named and the commit unit is chosen (per-slice by default)
- the user wants the process to keep running across turns or compaction cycles

Before handing off, prepare:

- phase set source
- selected branch
- target workspace
- delivery spec directory
- checkpoint policy
- commit unit
- completed Big Bang artifacts
- unresolved decisions
